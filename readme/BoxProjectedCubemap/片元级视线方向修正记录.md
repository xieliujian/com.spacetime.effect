# Box Projected Cubemap 片元级视线方向修正记录

[← 返回 盒子投影 Cubemap](BoxProjectedCubemap.md) · [← 算法原理](BoxProjectedCubemapDirectionCustom.md) · [← 返回主页](../../README.md)

> 记录日期：2026-11-04  
> 问题类型：平视时 Box Projected Cubemap 扭曲、纵向拉伸  
> 结论：Box 投影公式正确；根因是 Cube/Box Cube 采样复用了顶点归一化后插值的方向

---

## 1. 现象

大面积地板使用 Box Projected Cubemap 时，相机接近平视会看到反射方向扭曲、纵向拉伸，或者同一场景在不同工程中的结果不一致。

修改 Box 分辨率、反射强度或 Box 参数只能改变清晰度和覆盖范围，无法修正运动轨迹和方向形状。

## 2. 错误做法

顶点阶段可以先计算视线方向并归一化，这个结果可以继续用于 Rim、直接光和其他光照。错误是把同一个插值方向直接用于 Cube/Box Cube 采样：

```hlsl
// Vertex Shader
half3 viewDirWS = GetWorldSpaceViewDir(positionWS);
output.viewDirWS = SafeNormalize(viewDirWS);

// Fragment Shader
half3 reflectVector = reflect(-input.viewDirWS, normalWS);
```

这里发生了两次信息损失：

1. `viewDirWS` 在顶点阶段已经被归一化，只保留三个顶点的方向。
2. 片元阶段插值的是三个单位方向，而不是相机到当前像素的真实视线向量。

顶点归一化本身没有问题。问题在于透视投影下，归一化方向的变化不是线性的；三角形越大、相机越接近水平面，插值方向与相机到当前片元真实方向的偏差越明显。

Box Projection 会把该方向继续与 AABB 求交，反射方向稍微变化就会改变射线的命中面。接近地平线时，误差会被明显放大，因此表现为扭曲或拉伸。

## 3. 正确做法

顶点归一化保持不变。只在 Cube/Box Cube 计算前，让世界位置传递到片元阶段，并使用当前像素的世界位置重新计算用于反射的视线方向：

```hlsl
// Fragment Shader
float3 worldPos = input.positionWS;
float3 viewDirectionWS = _WorldSpaceCameraPos.xyz - worldPos;
half3 reflectVector = reflect(-viewDirectionWS, normalWS);

half3 sampleDirection = BoxProjectedCubemapDirectionCustom(
    reflectVector,
    worldPos,
    _BoxCubeReflCenter,
    _BoxCubeReflBoxMin,
    _BoxCubeReflBoxMax);
```

也可以使用 URP 封装：

```hlsl
float3 viewDirectionWS = GetWorldSpaceViewDir(input.positionWS);
```

该函数返回相机到当前位置的向量。`reflect()` 和 Cube 采样都不依赖该向量的长度，因此不应在计算反射前执行 `SafeNormalize()`。世界位置和视线向量应使用 `float3`，尤其大世界坐标在 10000 以上时，提前转换为 `half3` 会损失方向计算所需的精度。

正确原则是：

> 顶点归一化方向可以保留给其他光照；Cube/Box Cube 的方向由插值后的世界位置在片元阶段重新计算。

## 4. 为什么不是 Box 投影函数的问题

`BoxProjectedCubemapDirectionCustom` 的输入本来就是当前像素世界位置 `worldPos` 和反射方向 `worldRefl`。

函数内部实现是正确的：

- 从当前像素沿反射方向与 Box 求交。
- 选择最先命中的轴对齐平面。
- 返回从 Cube 中心指向命中点的方向。

只要传入的 `worldRefl` 来自顶点归一化后的插值方向，后面的 Box 求交就是在一个错误射线上继续计算，最终画面仍会扭曲。

## 5. 与 `GetCustomReflCubeDirection()` 的关系

在 Normal 模式下，`GetCustomReflCubeDirection()` 只执行 `normalize()`。Cubemap 采样本身也会归一化采样方向，因此删除该函数调用不能修复扭曲。

在 Matcap 模式下，该函数还负责应用 Matcap 旋转矩阵。正式材质、Box 投影和假反射预览必须保留同一套方向处理。

## 6. 在 SceneObjBaseLit 中的接入方式

`SceneObjBaseLit` 的自定义 Cube 有两条需要同步的片元路径：

1. 正式 PBR 自定义 Cube 采样。
2. 材质 Inspector 的假反射预览。

两条路径都必须使用当前片元的 `positionWS` 重新计算视线方向，再执行 `reflect()`、Box 投影和 Cubemap 采样。只修正式渲染会导致预览与最终结果不一致，只修预览则正式材质仍然扭曲。`SceneObjBaseLit` 顶点阶段的 `SafeNormalize()` 不需要删除。

## 7. 验证清单

1. 在地板上放置大面积四边形，让相机从高处逐渐降低到平视。
2. 确认反射方向连续变化，不出现突然拉伸或跳变。
3. 分别启用正式渲染和假反射预览，确认两者方向一致。
4. 固定同一 Cubemap 和 Box 参数，对比修改前后的截图。
5. 检查 Shader 日志，确认自定义 Cube 的 Normal、Matcap 和 Box Projection 变体均编译成功。
6. 在 OpenGL ES、Vulkan 和 Metal 目标上确认 `half` 精度不会引起新的量化跳变。

## 8. 排查时仍应检查的事项

- `_BoxCubeReflCenter`、`_BoxCubeReflBoxMin`、`_BoxCubeReflBoxMax` 是否来自同一个 Reflection Probe 包围盒。
- Cubemap 是否开启合适的 Mip、过滤和无缝设置。
- 地面网格是否包含超长三角形；片元级方向修复后，其他插值属性仍可能不足。
- 参考 Shader 是否为了局部地面效果硬编码了 `float3(0, 1, 0)`，而正式 Shader 使用的是实际表面法线。

## 9. Unity 工程中的采集路径

`SceneObjBaseLit` 的 Cube 采集应使用 Unity 自带 `ReflectionProbe` 渲染，而不是临时 `Camera.RenderToCubemap()`。接入方式为创建临时 Probe，同步采集点的盒体、LayerMask、HDR、分辨率和裁剪参数，然后调用 `RenderProbe()`，最后从 `realtimeTexture` 复制到可读 Cubemap 并导出。

这样可以保持与 Unity Reflection Probe Bake 相同的面朝向和内容来源。片元级视线修正仍然是必要的，因为它负责把 Probe 中心拍摄的 Cube 正确投影到当前像素。
